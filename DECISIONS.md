[2026-08-05] Lesson: first live Gemini test (real key, real image, real 6-candidate lighting category) failed with "Unterminated string in JSON". MaxOutputTokens: 1000 was too tight. Gemini 3.5's hidden "thinking" tokens (thoughtsTokenCount) count against maxOutputTokens, and with real (longer) product descriptions the response got cut off mid-JSON-string before the array closed. Fixed by raising maxOutputTokens to 3072 in app/api/analyze/route.ts. The 1000 figure in the original spec was tuned for Anthropic's non-thinking token accounting and doesn't transfer directly to Gemini 3.x models.
[2026-08-05] Lesson: the crossSell catch block silently swallowed errors with no logging (`catch { crossSell = null; }`), a direct violation of the "no silent failures" rule. [2026-08-05] Decision: the imageVerified toggle (app/api/dev/verify-image/route.ts) writes directly to lib/catalog.ts on disk via fs, located and replaced by locating the id marker then the next imageVerified field via plain string search. [2026-08-05] Decision: added automatic retry for Gemini 503 UNAVAILABLE (Google-side transient overload, confirmed live in production use). app/api/analyze/route.ts now wraps only the ai.models.generateContent call (not JSON parsing) in withRetry: up to 2 retries, 1s then 2s exponential backoff, gated on `err instanceof ApiError && err.status === 503` (the SDK's real error shape, confirmed by reading node_modules/@google/genai's compiled source). [2026-08-05] Verified: isolated tests against the actual ApiError class (not a mock) confirmed all four required behaviors: retries twice with correct 1s/2s timing and succeeds if a later attempt works; exhausts after 2 retries (3 total calls) and throws if persistently 503; does not retry at all on a 400 (1 call, throws immediately); does not retry on a generic non-ApiError (e.g. a JSON parse failure, 1 call, throws immediately).
