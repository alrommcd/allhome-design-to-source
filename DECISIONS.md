# Decisions: AllHome Design-to-Source Agent
<!-- Append-only. One line per entry. Never delete. -->
<!-- Format: [DATE] DECISION or LESSON: what and why. -->

[2026-08-04] Stack: Next.js 14 App Router + TypeScript + Tailwind, no database, single bundled catalog.ts. Matches build spec exactly — catalog never changes at runtime, a DB adds setup risk for zero benefit at this size.
[2026-08-04] Decision: switched from Anthropic to Google Gemini for the analyze route per explicit user instruction, mid-build. Package: @google/genai. Env var: GEMINI_API_KEY (not ANTHROPIC_API_KEY).
[2026-08-04] Decision: model pinned to gemini-3.5-flash, not the user-suggested gemini-3-flash. Verified via ai.google.dev/gemini-api/docs/models that gemini-3-flash only exists as gemini-3-flash-preview (preview-only); gemini-3.5-flash is the current GA flash model. Re-verify before shipping since Google renames these often.
[2026-08-04] Decision: use Gemini's native structured JSON output (config.responseMimeType: "application/json" + responseSchema) instead of prompting for JSON and parsing loosely — more reliable per user instruction, still defensively strips markdown fences before JSON.parse as a fallback.
[2026-08-04] Decision: template placeholder images (SVG "TEMPLATE PLACEHOLDER" cards) were rasterized to PNG with a one-off sharp conversion, since Gemini's inlineData image input does not accept image/svg+xml. sharp was not kept as a runtime dependency for that step — it was only needed once, at asset-prep time.
[2026-08-04] Lesson: those placeholder templates were replaced mid-build by Om with 4 real architectural renders (elevation.png, livingroom.png, reception.png, washroom.png) dropped directly into /public/templates. lib/templates.ts was updated to reference them with isPlaceholder: false — confirms the "swap files, no code changes needed" design in the spec works as intended.
[2026-08-04] Decision: sharp was re-added as a real dependency (not dev-only) once real photos landed in /public/templates, since next/image needs it to optimize local raster images in production builds.
[2026-08-04] Decision: cross-sell ("Also detected in this image") implemented as one extra Gemini call spanning all unselected categories' candidates combined, taking the single top-ranked result. The spec left the exact mechanism open ("may offer at most one cross-sell suggestion") — this keeps it to one additional call rather than one per unselected category.
[2026-08-04] Known gap: /api/analyze has never been exercised against the real Gemini API — no GEMINI_API_KEY was available during the build session. Verified only that the route correctly 500s with a clear error when the key is missing. Must be tested live before considering the Analyze feature done, per the "verified not written" rule.
[2026-08-05] Lesson: first live Gemini test (real key, real image, real 6-candidate lighting category) failed with "Unterminated string in JSON" — maxOutputTokens: 1000 was too tight. Gemini 3.5's hidden "thinking" tokens (thoughtsTokenCount) count against maxOutputTokens, and with real (longer) product descriptions the response got cut off mid-JSON-string before the array closed. Fixed by raising maxOutputTokens to 3072 in app/api/analyze/route.ts. The 1000 figure in the original spec was tuned for Anthropic's non-thinking token accounting and doesn't transfer directly to Gemini 3.x models.
[2026-08-05] Lesson: the crossSell catch block silently swallowed errors with no logging (`catch { crossSell = null; }`), a direct violation of the "no silent failures" rule — found during live testing when crossSell came back null with nothing in server logs to explain why. Fixed by adding console.error(err) before falling back to null.
[2026-08-05] Verified live end-to-end: real GEMINI_API_KEY, real livingroom.png, category "lighting". After the maxOutputTokens fix, both the primary 6-candidate ranking and the cross-category cross-sell call returned complete, valid, well-grounded results (rationales correctly referenced the room's actual pendant-light cluster, wall washes, and glass doors to the terrace; cross-sell correctly surfaced Window Factory sliding windows for the visible glass doors, an unselected "facades" category). One run's cross-sell call did fail transiently with no error captured before the logging fix landed — Gemini API latency/response variance on the larger 13-candidate cross-category prompt is a known characteristic, not something to paper over with silent retries.
[2026-08-05] Lesson: PROGRESS.md, DECISIONS.md, and earlier commit messages said "24 real seed products" — the catalog array was always correct, only the prose was wrong. Actual count is 22 (6 lighting + 6 facades + 6 hardware + 4 surfaces). Corrected in PROGRESS.md.
[2026-08-05] Decision: switched ProductImage.tsx from next/image to a plain <img> tag ahead of populating candidate imageUrls via automated search. next/image refuses to render remote hosts not explicitly listed in next.config.mjs's images.remotePatterns, and candidate images now span a growing, unpredictable set of brand domains (cloudfront, wixstatic, per-brand sites) — maintaining a per-host allowlist isn't worth it for a ~22-image catalog. Loses next/image's automatic format/lazy optimization, an acceptable tradeoff at this scale.
[2026-08-05] Decision: ran the "[Brand] [Product Line] India" automated image search (as directed) via 4 parallel research subagents, one per category, rather than sequentially in the main conversation — kept ~24 rounds of search/fetch results out of the main context, returning only a compact per-product JSON verdict from each agent.
[2026-08-05] Decision: research notes (naming mismatches, "no candidate found" reasons, weak-match caveats) live in a separate lib/reviewNotes.ts keyed by product id, not as a field on Product in lib/catalog.ts. Keeps the production data model free of dev-tool-only metadata; only app/review imports it.
[2026-08-05] Decision: the imageVerified toggle (app/api/dev/verify-image/route.ts) writes directly to lib/catalog.ts on disk via fs, located and replaced by locating the id marker then the next imageVerified field via plain string search — not regex. A regex-based version was tried first and silently failed to match anything; root cause was this environment's tool-call text losing one level of backslash escaping before bash ever sees it (confirmed with a minimal heredoc test: `\\s` written in the command arrived as `\s` in the file). Plain indexOf/slice sidesteps the whole class of bug and is easier to reason about for single-occurrence-per-product replacements like this anyway.
[2026-08-05] Decision: app/api/dev/verify-image is blocked with a 403 when NODE_ENV === "production" — it writes to a source file on disk, which is a dev-only concept (Vercel's filesystem is read-only/ephemeral at runtime regardless, so this would silently no-op or fail there anyway; the explicit guard makes that honest instead of confusing).
[2026-08-05] Result: automated image search found a candidate for 20 of 22 products; 2 came back null (ledlum-customised-indoor, ledlum-smart-lighting — Ledlum's site has no distinct page/image for either). All 22 remain imageVerified: false pending Om's manual review at /review.
